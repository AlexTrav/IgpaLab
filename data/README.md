# data: шаблоны АСУ и генератор синтетики

Реальной выгрузки пока нет, поэтому стенд работает на синтетическом датасете в формате выгрузок АСУ «ТУРАН». Генератор моделирует процесс целиком: студенты со скрытыми свойствами учатся, получают оценки, переходят с курса на курс, участвуют в мероприятиях, а затем часть достижений вносится в АСУ (с ошибками) и проходит согласование. Связи заданы явно, поэтому на стенде можно проверить, находят ли их модели. Обоснование: [docs/data.md](../docs/data.md).

## Запуск

```
make -C data generate                                         # версия synthetic/v1 (6000 студентов, ~30 с)
make -C data generate VERSION=v1-12k ARGS="--students 12000"  # проверка насыщения по объёму
make -C data csv                                              # CSV для просмотра в Excel (в git не идут)
make -C data test                                             # 24 теста
```

## Что внутри

| Путь | Содержание |
| --- | --- |
| `example/` | Шаблоны выгрузок АСУ от научного руководителя (не менять) |
| `generator/config.yaml` | Все допущения и заложенные эффекты (seed, доли, интенсивности, ошибки ввода, согласование) |
| `generator/university.yaml` | Факультеты, высшие школы и ОП «Туран» (сайт turan.edu.kz, собрано в TuranAssist) |
| `synthetic/v1/` | Сгенерированная версия |

Таблицы версии (Parquet):

| Файл | Строка | Что есть в реальной АСУ |
| --- | --- | --- |
| `students` | студент: псевдоним, факультет, высшая школа, ОП, уровень, год поступления, форма, язык | да (без высшей школы и уровня) |
| `latent` | скрытые свойства студента | нет: истина стенда, в признаки не идёт |
| `courses`, `gpa_semester`, `gpa_year` | оценки по дисциплинам, GPA семестра и года | нужно запросить отдельно (вопрос 2) |
| `enrollment` | студент × учебный год: курс, итог года (переведён, повторный курс, выпущен, отчислен, ушёл) | частично |
| `motivation` | мотивация по годам | нет: истина стенда |
| `records_true` | все достижения, как было на самом деле | нет |
| `records_asu`, `approvals` | записи АСУ и этапы согласования, раздел IGPA как будто работает с 2021 года | вопрос 1 |
| `records_asu_real`, `approvals_real` | сценарий «как в жизни»: раздел открыт 01.09.2026, прошлое вносят задним числом | вопрос 1 |
| `snapshots_year`, `snapshots_semester` | срез на конец года и семестра: GPA, баллы по 16 типам, iROS, SSCI, IGPA; `true_*` по истине, `obs_*` по АСУ | годовой срез = выгрузка IGPA |
| `snapshots_real` | срез на «сегодня» для сценария «как в жизни» | |
| `snapshots_year_eduscore` | те же годовые срезы по правилам EduScore | для сравнения правил |

Прочее: `asu/<дата>/` и `asu_real/<дата>/` – xlsx в формате шаблонов на конец каждого года и на «сегодня» (сводная по SSCI по образцу IROS, допущение); `ground_truth.json` – параметры и заложенные эффекты; `passport.md` – паспорт данных.

## Главные допущения

- Достижения учитываются за учебный год, IGPA считается с годовым GPA.
- В шапке выгрузок вместо ФИО сотрудника «Синтетические данные IgpaLab», вместо ФИО студентов псевдонимы «Студент 000123».
- В «Общий балл по IROS/SSCI» пишется коэффициент 0–1, в колонки типов – баллы учтённых записей.
- Влияние активности на оценки (`effects` в конфиге): научные достижения прошлого семестра у сильных студентов немного повышают баллы, перегрузка разовыми SSCI немного снижает.
